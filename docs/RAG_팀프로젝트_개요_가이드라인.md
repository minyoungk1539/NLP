## 1. 한 줄 요약

**Solar Mini 4 API로 객관식 질의응답 시스템을 만들고, 검색(RAG)과 에이전트 워크플로우(문항당 LLM 5회 이내)로 정확도를 올린 뒤, `LLM only → Baseline RAG → Improved RAG`를 비교해 영어 슬라이드로 발표한다.**
모델 가중치는 건드리지 않습니다. 바꿀 수 있는 것은 **문서(소스) · 청크 · 인덱스 · 검색 방식 · 프롬프트 · 에이전트 구성**입니다.

## 3. 허용 방법 & 참고 논문 (참고자료 §2)

**허용**: 프롬프트 엔지니어링, 청킹, 쿼리 재작성, 키워드/벡터/하이브리드 검색, 리랭킹, 커스텀 인덱싱, 멀티 에이전트 워크플로우

**LLM 호출 5회 규칙 상세**
- 문항당 **모든 에이전트를 합쳐 5회**까지 (에이전트마다 5회가 아님)
- 추론(reasoning), 검증(verification), 수정(refinement) 등 **모든 LLM 호출이 1회로 셈**
- **임베딩, LLM이 아닌 검색(BM25, FAISS, Wikipedia API 검색)은 횟수에서 제외**
- eval.py는 정답만 채점하지만, **호출 횟수와 API 파라미터는 제출 코드·실행 기록에서 검토될 수 있음** → 호출 로그를 남겨야 함

**참고 방법 (선택)**

| 방법 / 논문 | 접근 | 호출 수 감각 |
|---|---|---|
| Self-Consistency (Wang et al., 2023) | 독립적인 추론 경로를 여러 개 생성 → 다수결 | n회 (예: 3–5) |
| Self-Refine (Madaan et al., 2023) | 초기 답 → 스스로 비판 → 반복 수정 | 1 + 2×반복 |
| CRITIC (Gou et al., 2024) | 허용된 외부 근거·도구로 초기 답을 검증 → 비판 기반 수정 | 2–3회 |
| Let's Verify Step by Step (Lightman et al., 2024) | 단계별 검증으로 추론 오류를 찾아 개선 (검증기 학습 없이) | 2–3회 |
| Custom Multi-Agent | 검색 계획, 답 생성, 근거 검증, 비판, 최종 선택 등 역할 분리 | 최대 5회 |

> 다른 최신 논문 활용이나 **독창적인 방법·시스템 설계를 권장**합니다.

## 5. 입력 · 출력 · 평가 (참고자료 §4)

**입력**
- `prompts` 컬럼에서 질문과 선택지를 읽음. 연습 파일에는 `answers`도 있지만 **최종 평가 입력(held-out)에는 없을 수 있음**
- `question_id`가 있으면 보존, 없으면 `row-0001` 같은 고정 ID 부여 (현재 연습 파일에는 `question_id` 없음)
- **모든 문항을 입력 순서대로** 처리

**출력**: UTF-8 CSV, **정확히 두 컬럼**, 문항당 응답 1개
```
question_id,responses
row-0001,[ANSWER]: (D)
row-0002,[ANSWER]: (C)
```
- 응답마다 `[ANSWER]: (X)` 태그 **정확히 1개**. X는 **그 문항 선택지 안의 대문자**
- 설명은 선택. **DataFrame 인덱스 컬럼 넣지 않기** (`to_csv(index=False)`)

**평가**: 제출 응답은 **제공된 `eval.py`를 수정하지 않고** 돌아가야 함 (`Project/` 폴더에서 실행)
```bash
python run.py --input data/test_samples.csv --output responses.csv
python eval.py responses.csv data/test_samples.csv
```
- `eval.py`는 `question_id`가 아니라 **행 위치로 비교** → 순서 유지, 모든 행에 응답 1개씩 (API 오류로 빠진 행이 있으면 이후 전부 밀려서 틀림)
- 잘못되었거나 파싱이 안 되는 태그는 오답 처리

## 7. 슬라이드 내용 정리 (`docs/project_desc.pdf`)

### 7-1. 프로젝트 목표 (p.2)
| 학습 목표 | 해야 할 일 |
|---|---|
| API로 LLM 사용하기 | 입력을 구성하고, 반환된 답변을 살펴본다 |
| 외부 지식 제공하기 | 관련 문단을 검색해 입력에 포함한다 |

| 결과 평가하기 | 답변을 비교하고 실패 사례를 조사한다 |

### 7-2. 왜 RAG인가 (p.3–4)
> "유창한 답변도 근거가 없을 수 있다. 소스는 우리가 검증할 수 있는 근거를 준다."

| 정보 공백 | 예시 | 소스가 도움이 되는 이유 |
|---|---|---|
| 전문 지식 | 법리, 의료 가이드라인 | 필요한 정의·조건을 제공 |
| 비공개 정보 | 회사 내부 절차 | 공개되지 않은 로컬 규칙을 쓸 수 있게 함 |
| 변경된 정보 | 개정된 대학 규정 | 어느 규칙이 이 질문에 적용되는지 식별 |

| | 모델 지식 (파라미터) | 외부 지식 (컨텍스트) |
|---|---|---|
| 정보가 있는 곳 | 프로젝트 전에 학습된 가중치 | 질문마다 함께 넣는 문단 |
| 사용 가능해지는 방식 | 사전학습 모델 | 문서 검색 |
| **이번에 바꾸는 것** | **파라미터 업데이트 없음** | **소스, 청크, 선택된 문단** |
| 기여하는 것 | 언어 이해, 사전 지식 | 현재 과제에 대한 구체적 근거 |

### 7-3. 문제 유형 (p.5–7)
- **입력**: 질문 + 선택지 / **목표**: 근거가 가장 잘 뒷받침되는 선택지 고르기

| 구분 | ① Professional knowledge | ② Ewha |
|---|---|---|
| 출처 | **MMLU-Pro** 벤치마크 | `data/ewha.pdf` (이화여자대학교 학칙) |
| 분야 | 법, 심리학, 경영, 철학, 역사 | 재입학·제적, 성적, 전공, 학점, 출석, 재학연한 등 |
| 선택지 | 최대 10개 (A–J). **7개(A–G)인 문항도 있음** | 4개 (A–D) |
| 언어 | 영어 | 한국어 |

- 예시 1 (MMLU-Pro, p.6): "The ____ School of jurisprudence believes that the law is an aggregate of social traditions and customs…" (A Command … J Pragmatic). 슬라이드에는 정답 표기가 없고, 내용상 C Historical
- 예시 2 (이화, p.7): "재학생은 학기 시작 후 며칠 이내에 휴학을 신청해야 하는가?" (A 30일 · B 45일 · C 60일 · **D 90일**)

### 7-4. RAG 구조 (p.8–10)
```
[문서] → Extract Content → Chunking → Chunks → Embeddings → Vector Store
[User] → Question → Query Embedding → (Semantic Search) → Closest Results → Answer Generation → Answer
```
| 단계 | 목적 |
|---|---|
| 소스 읽기 | 문서 텍스트와 **위치(페이지 등)** 복원 |
| 유용한 문단 유지 | **규칙을 해석에 필요한 조건과 함께** 보존 |
| 의미 표현 | 임베딩으로 질문과 문단 비교 |
| 출처 참조 유지 | 선택된 근거를 **문서·페이지까지 추적 가능**하게 |

| 후보 문단 | 질문과의 관련성 |
|---|---|
| 휴학 조항 | 신청 기한과 적용 대상을 포함 ✅ |
| 졸업 요건 | 다른 학사 절차를 설명 ❌ |
| 불완전한 문장 | 기한 해석에 필요한 조건이 빠졌을 수 있음 ⚠️ |

### 7-5. 컨텍스트 조건 실험 (p.11)
| 조건 | 제공 정보 | 확인할 것 | 교수님 필기 |
|---|---|---|---|
| 외부 컨텍스트 없음 | 질문 + 선택지 | 모델의 답에 근거가 있는가? | **BL** |
| 관련 컨텍스트 | 같은 질문 + 휴학 조항 | 90일 조건을 올바르게 적용하는가? | ↑ |
| 무관한 컨텍스트 | 같은 질문 + 무관한 문단 | 문단이 도움이 안 된다는 걸 알아채는가? | ↓ |

### 7-6. 실패 유형 (p.12): 오답 분석 프레임
| 실패 유형 | 확인할 근거 | 가능한 개선 |
|---|---|---|
| **Missing source** | 컬렉션에 필요한 사실이 없음 | 적절한 문서 추가 |
| **Wrong passage** | 검색된 텍스트가 주제와 무관 | 쿼리·랭킹 개선 |
| **Missing condition** | 규칙과 예외가 다른 청크로 분리됨 | 청크 경계 수정 |
| **Incorrect application** | 올바른 문단은 있음 | 프롬프트·검증 개선 |

### 7-7. 개선 방법 (p.13–14)
| 방법 | 바꾸는 것 / 테스트할 질문 |
|---|---|
| **Query rewriting** ⭐필기 강조 | 정보 요구를 더 명확한 검색 쿼리로 |
